# 4.2 本地模板源

**状态：本地模板源第一、二阶段已实现**
**目标版本：4.2**
**更新时间：2026-08-10**

## 1. 背景

redc 当前只有一个远程模板源 `https://redc.wgpsec.org`。公开仓库适合分发通用 Terraform 场景，但不适合承载私有模板、内部配置和体积较大的二进制制品。

本功能为 redc-gui 增加本地目录模板源，使用户可以把私有模板放在本机目录中，与公开模板源并存。对于同名模板，本地源可以覆盖公开源，从而在不修改公开 `redc-template` 的情况下使用私有场景。

## 2. 目标

### 2.1 必须实现

1. 在 redc-gui 中添加、删除、启用和刷新本地模板目录。
2. 本地目录按照现有 `<provider>/<scene>` 结构扫描。
3. 本地模板与官方远程模板合并展示。
4. 同名模板默认由本地源优先提供。
5. 用户点击模板市场中的“拉取”即可安装本地模板，不需要手工复制目录。
6. 已安装模板记录来源，更新时继续从原来源获取。
7. 本地源路径不可用时保留已安装模板，不影响已有场景部署。
8. CLI、GUI、MCP 使用同一套来源解析规则。

### 2.2 制品边界

私有模板中的二进制制品、下载地址、压缩包密码和 URL 由模板维护者自行管理。redc 不上传、托管、签名或解析这些制品，只负责按模板声明的变量执行部署。

### 2.3 非目标

- 第一阶段不实现私有远程模板仓库和远程仓库登录。
- 不允许模板直接使用任意本地绝对路径作为 ECS `user_data` 下载地址。
- 不改变现有公开 registry 的 `index.json` 格式。
- 不让本地模板源绕过现有 Terraform 计划、校验和插件生命周期。
- 不实现本地制品上传、对象存储暂存、短期 URL 生成或下载代理。

## 3. 用户体验

### 3.1 添加本地源

入口：`设置 → 模板源 → 添加本地目录`。

用户通过系统目录选择器选择目录，例如：

```text
/Users/f0x/private-redc-templates
├── aliyun
│   └── vbdc
│       ├── case.json
│       ├── main.tf
│       └── variables.tf
└── aws
    └── internal-proxy
```

保存后立即执行一次扫描，并在模板源列表显示：来源名称、路径、模板数量、启用状态和最近扫描结果。

### 3.2 模板市场

模板市场将官方远程源和本地源合并为一个列表：

- 本地源模板显示“本地”来源标识。
- 本地源和官方源存在相同模板 ID 时，只显示优先级最高的版本。
- 模板详情 README 优先读取实际提供该模板的来源。
- 点击“拉取”时不需要用户选择路径；系统使用解析后的来源自动安装。
- 本地源目录发生版本变化后，刷新列表即可显示更新状态。

### 3.3 用户最终操作

```text
1. 设置中添加一次私有模板目录
2. 模板市场刷新
3. 拉取 aliyun/vbdc
4. 正常创建和部署场景
```

## 4. 来源模型

### 4.1 数据结构

新增 `mod/template_source.go`：

```go
type TemplateSourceType string

const (
    TemplateSourceRemote TemplateSourceType = "remote"
    TemplateSourceLocal  TemplateSourceType = "local"
)

type TemplateSource struct {
    ID          string             `json:"id"`
    Name        string             `json:"name"`
    Type        TemplateSourceType `json:"type"`
    Path        string             `json:"path,omitempty"`
    URL         string             `json:"url,omitempty"`
    Priority    int                `json:"priority"`
    Enabled     bool               `json:"enabled"`
    ReadOnly    bool               `json:"read_only"`
    LastScanAt  string             `json:"last_scan_at,omitempty"`
    LastError   string             `json:"last_error,omitempty"`
    TemplateCount int              `json:"template_count"`
}
```

第一阶段只持久化 `local` 来源；官方远程源作为内置来源保留，不要求用户手工添加。

### 4.2 配置存储

来源描述保存到：

```text
<redc-path>/template-sources.json
```

该文件只包含路径和来源元数据，不包含访问令牌。写入使用临时文件加原子替换，文件权限至少为 `0600`，避免本地模板路径泄露给其他用户。

来源 ID 在首次添加时生成并持久化，不根据显示名称生成。修改名称或路径不会改变来源 ID，便于已安装模板继续追踪来源。

### 4.3 扫描规则

复用 `ScanTemplateDirs` 和 `readTemplateMeta`：

1. 对来源路径执行 `filepath.Abs` 和 `filepath.EvalSymlinks`。
2. 拒绝不存在、非目录和无法读取的路径。
3. 只扫描最大深度内的模板目录。
4. 每个模板目录必须包含合法 `case.json`。
5. 忽略 `.git`、`.terraform`、状态文件和无法解析的目录。
6. 记录扫描错误，但单个坏模板不能阻断其他模板显示。
7. 访问文件时校验最终路径仍位于来源根目录内，防止符号链接逃逸。

### 4.4 合并与优先级

模板的唯一键为相对路径，例如 `aliyun/vbdc`。

合并顺序：

```text
priority 降序 → source ID 升序 → template ID 升序
```

默认优先级：

| 来源 | 默认优先级 |
|------|-----------:|
| 本地目录 | 100 |
| 官方远程源 | 0 |

同一个模板 ID 只保留排序后第一项，其他来源记录为冲突信息，供日志和调试使用。

### 4.5 已安装模板来源

在 `<redc-path>/template-installations.json` 记录：

```json
{
  "aliyun/vbdc": {
    "source_id": "local-8c3d...",
    "version": "1.0.0",
    "installed_at": "2026-08-10T12:00:00Z"
  }
}
```

安装来源记录不写入模板目录，避免修改模板压缩包内容。来源目录被删除后：

- 已安装模板继续可用；
- 模板市场显示来源不可用；
- 更新操作提示重新配置来源；
- 不自动删除已安装模板或已有部署。

## 5. 后端设计

### 5.1 来源管理器

新增 `TemplateSourceManager`，负责：

- 加载和保存来源配置；
- 扫描本地目录；
- 获取内置远程源索引；
- 合并模板元数据；
- 根据模板 ID 解析实际来源；
- 安装模板并记录来源；
- 检测来源冲突和失效状态。

现有 `ListLocalTemplates`、`GetRemoteIndex`、`Pull` 的具体网络或文件操作下沉到来源实现，避免在 GUI、CLI 和 MCP 中分别实现来源逻辑。

建议接口：

```go
type TemplateSourceManager interface {
    ListSources() ([]TemplateSource, error)
    AddLocalSource(name, path string) (*TemplateSource, error)
    UpdateSource(source TemplateSource) error
    RemoveSource(sourceID string) error
    ScanSource(sourceID string) ([]*RedcTmpl, error)
    ListMergedTemplates() ([]*RegistryTemplate, error)
    ResolveTemplate(name string, sourceID string) (*ResolvedTemplate, error)
    InstallTemplate(ctx context.Context, name, sourceID string, force bool) error
}
```

### 5.2 Wails API

`App` 新增以下方法：

```go
ListTemplateSources() ([]TemplateSource, error)
AddLocalTemplateSource(name, path string) (TemplateSource, error)
UpdateTemplateSource(source TemplateSource) error
RemoveTemplateSource(sourceID string) error
ScanTemplateSource(sourceID string) ([]ResolvedTemplate, error)
FetchMergedTemplateRegistry(registryURL string) ([]RegistryTemplate, error)
PullTemplate(templateName string, force bool) error
```

现有 `FetchRegistryTemplates(registryURL string)` 和 `PullTemplate(templateName, force)` 的 Wails 绑定需要保持兼容。新增的 `FetchMergedTemplateRegistry()` 专门返回来源管理器合并后的结果，避免 Go/Wails 不支持方法重载。旧 `FetchRegistryTemplates(registryURL string)` 继续用于显式查询单一远程源。

### 5.3 CLI 和 MCP

新增 CLI 管理命令：

```bash
redc template-source list
redc template-source add-local <name> <path>
redc template-source scan <source-id>
redc template-source remove <source-id>
```

现有命令保持不变：

```bash
redc pull aliyun/vbdc
```

可选增加 `--source <source-id>` 以绕过默认优先级，用于调试或显式选择官方版本。

MCP 的 `search_templates` 和 `pull_template` 默认走来源管理器；已有 `registry_url` 参数保留，作为临时远程源覆盖参数。

## 6. GUI 设计

### 6.1 设置页模板源区域

位置：`frontend/src/components/Settings/Settings.svelte`。

列表列：

| 列 | 内容 |
|----|------|
| 名称 | 用户定义的来源名称 |
| 类型 | 本地目录 |
| 路径 | 可换行显示的绝对路径 |
| 状态 | 已连接、目录不存在、扫描失败、已禁用 |
| 数量 | 扫描到的模板数量 |
| 优先级 | 数值输入或上下移动按钮 |
| 操作 | 扫描、编辑、禁用、删除 |

添加对话框：

- 名称输入；
- 系统目录选择器；
- 选择后显示规范化路径；
- 保存前执行扫描；
- 扫描失败时保留错误原因，不保存无效来源。

### 6.2 模板市场变更

`Registry.svelte` 改为使用合并后的 `FetchMergedTemplateRegistry()` 结果，只增加：

- `sourceId`、`sourceName`、`sourceType` 字段；
- 来源标识和不可用状态；
- 拉取时传递解析后的来源信息（或由后端自动解析）；
- 本地源模板与官方源同名时显示最终生效项。

### 6.3 错误状态

必须区分：

- 来源目录不存在；
- 来源目录无权限；
- 来源存在但模板 `case.json` 损坏；
- 同名模板冲突；
- 安装复制失败；
- 已安装模板的来源失效。

错误应显示在来源行或 Toast 中，不能只写入日志。

## 7. 制品边界

本地模板可以包含 Terraform、脚本和私有配置，也可以把下载 URL 写入 `variables.tf` 默认值或 `terraform.tfvars`。redc 不判断 URL 的来源，不代替用户上传文件，也不修改制品的生命周期。

以 vbdc 为例，私有模板可以自行维护：

```hcl
variable "vbdc_download_url" {
  type      = string
  sensitive = true
  default   = "https://private.example.com/vbdc/v1.0.0/vbdc_linux_amd64.zip"
}
```

如果模板不希望把 URL 写入文件，也可以继续声明为必填变量，由用户在部署参数中提供。该行为属于模板自身契约，不由本地模板源功能改变。

### vbdc 迁移

vbdc 私有模板放在用户配置的本地源目录中，并在私有模板的 `variables.tf` 默认值或 `terraform.tfvars` 中维护 vbdc 和 lazywatch 下载地址。公开 `redc-template` 只保留通用公开场景，不承载这些私有 URL 或二进制制品。

## 8. 安全要求

1. 本地源扫描不执行任何模板脚本。
2. 安装和部署仍复用现有 Terraform 校验、计划和插件钩子。
3. 来源路径、模板名和文件名全部做路径穿越检查。
4. 不允许通过来源路径读取其根目录之外的符号链接目标。
5. 私有制品下载地址和密码不得写入 redc 日志。
6. Terraform 参数和状态文件可能包含模板中的 URL 或敏感变量，GUI 需要提示用户保护任务目录。
7. 本地模板来源默认只读；编辑动作必须明确写入源目录或复制到托管目录。

## 11. 待决策项

以下项目会影响实现边界，需要确认：

| 编号 | 问题 | 推荐选择 | 影响 |
|------|------|----------|------|
| D1 | 本地源模板使用方式 | **复制安装到 `redc/templates`** | 保持现有部署、删除和缓存逻辑稳定；源目录可只读 |
| D2 | 同名模板冲突 | **本地源优先，官方源隐藏为备用项** | `aliyun/vbdc` 可覆盖公开模板 |
| D3 | 来源目录消失 | **保留已安装副本，不自动删除** | 避免路径移动导致已有场景不可用 |
| D4 | 本地源编辑 | **默认只读，编辑器另存为托管模板** | 避免 GUI 意外修改私有源目录 |

以上选择可以作为默认行为直接实现；如果没有特别要求，按推荐方案执行。
